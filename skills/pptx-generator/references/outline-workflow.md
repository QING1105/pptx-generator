# 从材料到逐页提纲

## 选择制作方式

- **方式 1｜已有提纲，直接生成。** 接收已有的 JSON、文档或聊天提纲，保留用户给定的标题、目录顺序、各节内容和排版要求。先整理成 `outline.json` 并校验，随后生成 PPT。已有提纲时，围绕影响生成的缺项或互相矛盾的要求补问。
- **方式 2｜苏格拉底式问答，生成提纲。** 先读用户提供的论文、实验图表或讲稿。从汇报目的、听众、时长和主线开始，再按章节用少量问题逐轮确认。把已经从材料读到的内容作为起点，向用户追问需要取舍的部分。

在问答中，可以依次讨论这些问题。

1. 听众听完应该记住哪条结论？这条结论回答了什么问题？
2. 哪些背景信息对理解结论最重要？方法讲到哪一步才足以读懂结果？
3. 哪张图或哪组数据支撑这一页的讲述重点？图号、比较对象和结果方向分别是什么？
4. 下一节如何接上这一节？在总时长里，哪些内容应展开，哪些适合放在备用页？
5. 有哪些明确的排版要求？例如结果页采用左图右文，方法页用流程图，整章沿用某份现有模板。

按场合选问题。答辩可以用[答辩追问清单](presets/defense-final.md)。文献汇报先从论文提取问题、方法、证据和结论，再与用户确认讲述重点、图表选择和需要讨论的问题。

方式 2 在确认章节主线后，保存一版 JSON，并用逐页表在当前聊天中展示页标题、讲述要点、图表依据和版式。按反馈更新同一份文件，收到对提纲的确认后再生成 PPT。用户只要求提纲时，交付 JSON 和可读预览。

## 提纲文件格式

[完整 JSON 示例](outline.example.json)可以复制到演示项目目录，命名为 `outline.json`。用 UTF-8 保存。

| 字段 | 类型 | 含义 |
|---|---|---|
| `schema_version` | 整数 | 格式版本。目前为 `1` |
| `revision` | 正整数 | 提纲修改次数的版本标记。首版为 `1`，每次保存实际修改后加一 |
| `presentation.title` | 字符串 | 报告标题 |
| `presentation.occasion`、`audience`、`language` | 字符串 | 场合、听众和汇报语言 |
| `presentation.duration_minutes` | 正数或 `null` | 总时长，单位为分钟 |
| `presentation.style_code` | 字符串或 `null` | S1–S4、M1–M5 或 O1–O18。沿用模板原样式或待定时可填 `null` |
| `presentation.template_file` | 字符串或 `null` | 要沿用的 PPTX 文件。项目内文件用相对于 `outline.json` 的路径 |
| `presentation.layout_requirements` | 字符串数组 | 全稿的版式要求，例如画布比例、字体、页码位置或单位模板规范 |
| `sections[]` | 数组 | 各章节及其顺序，也是目录的来源 |
| `sections[].id`、`title` | 字符串 | 章节固定 ID 和显示名称 |
| `sections[].show_in_toc` | 布尔值 | 该章是否显示在目录页。开场、致谢和备用页可按需排除 |
| `sections[].layout_requirements` | 字符串数组 | 整章都要遵循的排版要求，空数组表示交给制作者安排 |
| `sections[].slides[]` | 数组 | 该章下各页及其顺序 |
| `slides[].id`、`title` | 字符串 | 单页固定 ID 和标题。首张封面的标题与报告标题一致 |
| `slides[].type` | 枚举 | `cover`、`toc`、`divider`、`content` 或 `summary` |
| `slides[].key_message` | 字符串 | 这一页要让听众记住的重点。内容和总结页填写要点，封面、目录、分隔页可留空 |
| `slides[].content` | 字符串数组 | 要显示在幻灯片上的内容。目录条目自动取 `sections` 的标题和顺序 |
| `slides[].sources` | 字符串数组 | 支撑本页内容的来源，例如论文页码、DOI、原始表格名或图号 |
| `slides[].visuals` | 对象数组 | 每个图表写 `file`、`source`、`caption`。文件尚未提供时将 `file` 设为 `null`，保留图号或来源以便补齐 |
| `slides[].layout.code` | 字符串或 `null` | L1–L16。沿用模板页或交给制作者时可填 `null` |
| `slides[].layout.requirements` | 字符串数组 | 单页排版要求。例如优先保留图宽，正文放右侧 |
| `slides[].speaker_notes` | 字符串数组 | 演讲时要说的要点，可含引入下一页的过渡句 |

所有表中字段都保留。确实没有内容的数组写 `[]`，允许留空的文本写 `""`，待确定或不适用的可空字段写 `null`。素材路径相对于提纲所在目录。章节和单页的 ID 用小写字母、数字和连字符，整个文件中每个 ID 唯一。目录页允许省略。保留目录页时，标记 `show_in_toc: true` 的章节按顺序显示，并将该页的 `content` 留空。

## 修改、校验和生成

1. 优先打开项目已有的 `outline.json`。按 ID 修改需要变动的章节或页面，重排时移动数组成员并保留原 ID。
2. 保存实际修改后递增 `revision`。同一次修改中的章节名、目录、页序和引用一起核对。重复生成同一份提纲时沿用原版本号。
3. 用下方命令校验。它会定位缺失字段、重复 ID、无效的风格或版式编号，以及手填目录等会导致前后矛盾的问题。图表出处和事实准确性由制作时根据来源核对。

   ```text
   node scripts/validate-outline.cjs "<演示项目目录>/outline.json"
   ```

4. 按校验通过的 JSON 生成 PPTX。全稿、章节和单页的排版要求一起应用。用户交由制作者决定版式时，把实际选择写回 JSON。沿用模板页时，在单页排版要求中记录原模板页码或用途。发现互相矛盾的要求时先和用户确认，更新 JSON 后再生成。
5. 最终核对 PPTX 的页数、标题、顺序和目录与 JSON 一致。后续改稿先改这份 JSON，再更新相关幻灯片。交付时把提纲文件和 PPTX 一并给用户。
